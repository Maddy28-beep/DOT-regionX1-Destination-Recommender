# Visible QR review comments and optional ratings

After a signed establishment QR scan, travelers now see Overall, Service, Amenities and Comments or suggestions directly on the review form. Only Overall is required. Service, amenities and text are no longer hidden behind Add details. Tapping stars does not submit; the traveler uses Post my review after completing the fields they want. Comment validation errors are visible.

A traveler who already submitted an overall-only review can return in the same browser and use Add your remaining feedback. This form exposes only unanswered optional ratings and/or a missing comment. It saves them on the original review, preserving its ID, overall rating, original creation date and review count. Existing answered feedback cannot be overwritten through this endpoint. A browser that lost its cookie cannot claim a previous review, and completing another visitor's review is forbidden.

The new throttled, CSRF-protected POST `/reviews/{type}/{id}/feedback` checks the listing, QR check-in and ownership by browser token. It validates 1–5 aspect ratings and a 500-character comment, requires at least one supplied field, and locks the existing row before filling missing values so concurrent requests cannot replace answers. Completion redirects to the Traveler Reviews section. No second review row or recalculation of the unchanged overall average is required.

DOT Visitor Feedback → Written reviews shows the text, overall score and provided Service/Amenities scores. Its statistics read the completed aspect values from the same review. Existing date/establishment filters still apply. The original review date is retained, so an older review may require a wider date filter. No token is displayed. Text remains Blade-escaped. The partner's Guest Reviews statistics use the same stored aspect ratings.
