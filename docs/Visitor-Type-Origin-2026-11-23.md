# Visitor choices follow declared origin

The origin-first planner now offers First-time Visitor and Returning Visitor for origins outside Davao Region, including other Philippine provinces. A Philippine origin in one of the five Region XI provinces also offers **I live in Davao Region**. The visitor explicitly selects it; country/province does not automatically establish residency, and GPS is not used for this classification. Frequent visitors from elsewhere select Returning Visitor.

New resident submissions store `Davao Region Resident`. The server rejects both that value and the legacy `Regular / Local` value for non-Davao or incomplete origins before saving a trip. An eligible legacy local submission normalizes to the new resident value. The original visitor-frequency question remains unchanged when `trip_location_v2` is off.

The recommendation service recognizes the new value with exactly the previous local weighting. Exit survey context and admin filter options accept it while retaining the legacy value for historical records. No historical trip or survey rows are rewritten. Old combined regular/local answers display as Returning for nonlocal origins, or as the resident option for eligible origins. Old local drafts use the same mapping when resumed; a modern resident draft outside the region is cleared and requires a new answer.

Client controls react to country/province changes and remembered-origin restoration. Disallowed resident controls are hidden and disabled; changing away from a local origin clears an existing resident selection. Two or three columns fit the available choices on desktop, with one column on phones. Origin confirmation, origin counting, pick-up handling and the remaining trip preferences retain their existing behavior.
