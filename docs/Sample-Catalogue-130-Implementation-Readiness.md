## Approach

Reuse what exists, build only the missing import path, and keep provenance mechanical: `is_accredited = true` purely as the eligibility flag, plus exactly one placeholder accreditation record (`SAMPLE-####`, `is_placeholder = true`, Active to 2030-12-31) per listing so `SampleData` classifies it `sample` everywhere. Import in dry-run-first, all-or-nothing transactions per kind, exactly like the existing destination sample importer. Build embeddings only after records exist. Ship visibility precondition G3 (chatbot wording) before public exposure; G1, G2, G4, G5 in the same release. Deploy the data import as a manual post-deploy step, never wired into `deploy/server-update.sh`, so a code deploy can never silently create test data.

## Steps

### Phase A — Importer preparation (code)

1. Extend `app/Console/Commands/ImportSampleDestinations.php` (`sample:import-destinations`): accept `category_tags` and `amenity_tags` CSV columns and write `destination_tags` rows (kind `category` / kind `amenity`, amenity values as exact `App\Support\Amenities` catalogue labels). Verified gap: today the importer creates the destination and its placeholder accreditation but writes no tags, which would starve interest matching. Keep its existing guarantees: dry-run by default, all-or-nothing transaction, ` [SAMPLE]` suffix enforcement, coordinates required inside Region XI bounds, duplicate rejection (existing slug, live name, filename), `SAMPLE-####` sequencing from the current maximum, and `--remove` limited to placeholder-plus-suffix records. Reuse: the whole command skeleton, `plain()` name normalisation, and region lookup.
2. Create a new command `sample:import-listings` for accommodations, restaurants, and souvenir centres (one command, `--kind=accommodation|restaurant|souvenir_center`, same file discipline). Verified: no existing importer can create these kinds as samples — `listings:apply-updates` only edits existing rows by id plus name, `dot:sync-dataset` only syncs DOT-dataset coordinates and accreditation dates, and `AccreditationSeeder` backfills placeholders with mixed Expired/Expiring statuses and is explicitly not reused. The new command must: require coordinates and Region XI bounds; validate type/cuisine against existing vocabularies; write amenities through `App\Services\Amenities\AmenityStore::sync()` (kind-legal keys only, at least 4); for accommodations write `accommodation_room_types` rows (name, price_min, price_max) bracketing `price_per_night` and set `resort_settings` via the model's encoder; create the single placeholder accreditation record; support dry-run, `--apply`, and triple-guarded `--remove` (placeholder record plus `SAMPLE-%` number plus name suffix).
